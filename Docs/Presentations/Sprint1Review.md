# Software Design Learning

## SOLID Principles

**Design principle learned:** SOLID software design principles.

### Why It Matters

- Encourages clear separation of concerns.
- Makes components easier to understand.
- Supports maintainable and extensible code.
- Reduces unnecessary coupling between responsibilities.

### Application & Results

Applying SOLID principles helped guide the implementation toward clearer separation of responsibilities and a more organized project structure.

# Sprint 2 Plan

## MVP Goals

**Primary goal:** Create at least 3 playable puzzles with clear navigation.

### MVP Objectives

- Create at least three playable puzzles.
- Implement clear navigation between game states and puzzles.
- Connect drawing interactions with in-game effects.
- Establish a functional puzzle creation framework.

### Success Criteria

- Players can navigate the game clearly.
- At least three puzzles are playable.
- Drawing affects appropriate game objects.
- Core gameplay is ready for testing and refinement.

# Sprint 2 Testing Strategy

## Required Test Plan

| Test Type | Implementation Plan |
|:--|:--|
| Unit Tests | Implement when the majority of the framework is finished. |
| Integration Tests | Implement when the majority of the framework is finished. |
| Regression Tests | Implement when the majority of the framework is finished. |
| Acceptance Tests | Implement when the majority of the framework is finished. |

### Testing Objectives

- **Unit testing:** Verify individual components and functions.
- **Integration testing:** Confirm that drawing, objects, and puzzle logic work together.
- **Regression testing:** Ensure new features do not break existing functionality.
- **Acceptance testing:** Verify the game meets its MVP goals and is usable by players.

### Approach

Build the core framework first, then introduce systematic testing as the major components become available.
